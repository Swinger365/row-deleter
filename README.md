# xlsx_red_cleaner

Консольная программа на C++17, которая на указанных листах книги Excel (`.xlsx`), начиная
с заданной строки, очищает содержимое всех строк, где есть хотя бы одна ячейка красного цвета.

Очистка работает как команда Excel «Очистить содержимое»: из ячеек удаляются значения и формулы,
а форматирование (стиль, а значит и сама красная заливка), размеры строк, объединения и всё
остальное в книге остаются как были.

Готовый исполняемый файл для Windows (x86-64, Windows 10 и новее, без дополнительных DLL)
лежит в [`executable/xlsx_red_cleaner.exe`](executable/xlsx_red_cleaner.exe).

## Возможности

- Обработка выбранных листов, у каждого может быть своя начальная строка (`-s "Лист:5"`),
  или сразу всех рабочих листов (`--all-sheets`).
- Красной считается заливка ячейки (по умолчанию), цвет шрифта или любое из двух.
- Цвета понимаются во всех формах, которые пишет Excel: `rgb`, цвета темы с осветлением
  или затемнением (`theme` + `tint`), индексированная палитра (стандартная и `<indexedColors>`
  из книги), узорные и градиентные заливки.
- Многопоточность на всех тяжёлых этапах, в том числе при сжатии одной большой части архива.
- Результат не зависит от числа потоков: выходной файл побайтно одинаков при любых `-j`.
- Корректная работа с формулами:
  - если очищается главная ячейка общей формулы (`t="shared"`), зависимые ячейки получают
    свои формулы со сдвинутыми ссылками;
  - если удалялись формулы, удаляется `calcChain.xml`, и Excel пересоздаёт его сам.
    Без этого Excel сообщил бы о повреждении файла.
- Неизменённые части книги копируются из исходного архива без распаковки и пересжатия.
- Запись идёт через временный файл, поэтому при ошибке исходная книга не портится.
  Можно перезаписывать входной файл (`--in-place`).
- Пробный запуск (`--dry-run`) показывает, какие строки будут очищены, ничего не меняя.
- Пути и имена листов в Юникоде, в том числе в Windows.

## Что считается красным

По умолчанию цвет переводится в HSV, и красным считается цвет, у которого:

| Параметр | Условие | Опция |
|---|---|---|
| Оттенок | не дальше 20° от чистого красного (0°) | `--hue-tolerance` |
| Насыщенность | не меньше 0.5 | `--min-saturation` |
| Яркость | не меньше 0.5 | `--min-value` |

Так красными считаются `FF0000`, тёмно-красный Excel `C00000` и похожие оттенки, а бледно-розовый
(`FFC7CE`, стиль «Плохой»), оранжевый, бордовый почти чёрный — нет.

Если нужны точные цвета, их можно перечислить: `--colors FF0000,C00000`. Тогда эвристика
не используется и красными считаются только эти цвета.

## Сборка

Нужны CMake 3.20+, компилятор C++17 и доступ в интернет при первой конфигурации:
CMake сам скачает зависимости через `FetchContent`.

### Linux

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build -j4
```

Исполняемый файл: `build/xlsx_red_cleaner`. Тесты можно отключить опцией `-DRED_CLEANER_BUILD_TESTS=OFF`.

### Windows: нативная сборка

Visual Studio 2019+ или MinGW-w64:

```bat
cmake -S . -B build
cmake --build build --config Release
```

### Windows: кросс-сборка из Linux

Используется [llvm-mingw](https://github.com/mstorsjo/llvm-mingw) (или пакет `mingw-w64`)
и файл toolchain из проекта. Файл в `executable/` собран так:

```sh
cmake -S . -B build-windows \
      -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64-x86_64.cmake \
      -DMINGW_ROOT=/путь/к/llvm-mingw \
      -DCMAKE_BUILD_TYPE=Release -DRED_CLEANER_BUILD_TESTS=OFF
cmake --build build-windows -j
```

`MINGW_ROOT` можно не указывать, если компиляторы `x86_64-w64-mingw32-*` есть в `PATH`.
Программа линкуется статически и зависит только от системных библиотек Windows.

### Документация

Документация генерируется Doxygen (нужен также Graphviz для диаграмм):

doxygen Doxyfile                    # или: cmake --build build --target docs

## Использование

```text
xlsx_red_cleaner -i ВХОД.xlsx (-o ВЫХОД.xlsx | --in-place | --dry-run) -s ЛИСТ[:СТРОКА]... [опции]
```

Примеры:

```sh
# Листы «Отчёт» (со строки 2) и «Данные» (со строки 5), результат в новый файл
xlsx_red_cleaner -i книга.xlsx -o результат.xlsx -s "Отчёт:2" -s "Данные:5"

# Все листы со строки 3, перезаписать исходный файл
xlsx_red_cleaner книга.xlsx --in-place --all-sheets -r 3

# Посмотреть, какие строки будут очищены, если красным считать и шрифт, и заливку
xlsx_red_cleaner -i книга.xlsx -s Лист1 --target any --dry-run -v

# Только точные цвета, 8 потоков, быстрое сжатие
xlsx_red_cleaner -i in.xlsx -o out.xlsx -s Лист1 --colors FF0000,C00000 -j 8 --compression-level 1
```

Пример вывода:

```text
Стилей ячеек: 4, из них красных: 2; потоков: 4
Лист "Отчёт" (со строки 2): просмотрено строк 20, строк с красными ячейками 5, очищено ячеек 13
  строки: 5, 7, 9, 15, 22
Сохранено в "результат.xlsx"
Время: 0.0277 с
```

### Опции

| Опция | Описание |
|---|---|
| `-i`, `--input FILE` | Входной файл `.xlsx`; можно указать без опции. |
| `-o`, `--output FILE` | Куда сохранить результат. |
| `--in-place` | Перезаписать входной файл. |
| `-s`, `--sheet NAME[:ROW]` | Лист для обработки, можно повторять; `ROW` — своя начальная строка. |
| `--all-sheets` | Обработать все рабочие листы (не совмещается с `--sheet`). |
| `-r`, `--start-row N` | Начальная строка по умолчанию (1). |
| `-t`, `--target WHAT` | `fill` — заливка (по умолчанию), `font` — цвет шрифта, `any` — любое. |
| `--colors LIST` | Точный список цветов `RRGGBB` через запятую. |
| `--hue-tolerance D` | Допуск оттенка в градусах (20). |
| `--min-saturation X` | Минимальная насыщенность 0..1 (0.5). |
| `--min-value X` | Минимальная яркость 0..1 (0.5). |
| `-j`, `--threads N` | Число потоков (по умолчанию — число ядер). |
| `--rows-per-task N` | Строк в одной задаче поиска (4096). |
| `--compression-level N` | Уровень сжатия 1..9 (6); 1 заметно быстрее, файл немного больше. |
| `--dry-run` | Только показать, что будет очищено. |
| `-v`, `--verbose` | Вывести номера найденных строк и время этапов. |
| `-h`, `--help` | Справка. |

Опции со значением можно писать и как `--opt=значение`.

Коды возврата: `0` — успех, `1` — ошибка при обработке файла (не найден, повреждён, нет листа
и т.п.), `2` — ошибка в аргументах командной строки.

## Как это устроено

Файл `.xlsx` — это zip-архив с XML-частями. Программа:

1. Читает связи пакета (`_rels/.rels`, `xl/_rels/workbook.xml.rels`), находит листы, стили и тему.
2. Строит из `styles.xml` таблицу «индекс стиля → красный или нет». После этого цвет каждой
   ячейки проверяется одним обращением к массиву по атрибуту `s`.
3. Обрабатывает листы в несколько параллельных этапов на общем пуле потоков:

| Этап | Параллелизм |
|---|---|
| Распаковка и разбор XML листов | по задаче на лист |
| Поиск красных строк | куски по `--rows-per-task` строк всех листов вперемешку; документы только читаются |
| Очистка и сериализация XML | по задаче на лист (pugixml не допускает параллельной записи в один документ) |
| Сжатие изменённых частей | каждая часть режется на куски по 4 МиБ, куски сжимаются независимо и склеиваются в один корректный deflate-поток |
| Запись архива | последовательно; неизменённые части копируются без пересжатия |

Исходный код находится в `src/`:

| Файл | Назначение |
|---|---|
| `main.cpp` | точка входа, вывод отчёта, Юникод-аргументы в Windows |
| `cli.*` | разбор командной строки |
| `cleaner.*` | вся операция целиком: этапы и пул потоков |
| `xlsx_package.*` | пакет OOXML: связи, листы, чтение и сохранение частей |
| `zip_archive.*` | zip поверх miniz, параллельное сжатие кусками |
| `styles.*` | разбор `styles.xml` и темы, таблица красных стилей |
| `color.*` | цвета: hex, HSV, tint, индексированная палитра, критерий красного |
| `sheet_processor.*` | поиск и очистка строк одного листа |
| `formula.*` | адреса ячеек и сдвиг ссылок в формулах |
| `thread_pool.hpp` | пул потоков, `parallelFor`, `waitAll` |
| `xml_utils.*` | помощники для pugixml с учётом префиксов пространств имён |

### Почему pugixml и miniz, а не готовая библиотека для Excel

Сначала рассматривался [OpenXLSX](https://github.com/troldal/OpenXLSX), самая развитая
C++-библиотека для `.xlsx`. Для этой задачи она не подошла:

- при обходе строк она дописывает в документ недостающие строки и ячейки, поэтому читать
  её из нескольких потоков нельзя;
- при чтении цвета она изменяет `styles.xml` и понимает только `rgb`, а цвета темы
  и индексированной палитры не понимает;
- её zip-слой однопоточный. На большой книге около 75% времени уходило на сжатие,
  и многопоточность почти ничего не давала.

Другие варианты хуже: xlnt при сохранении теряет диаграммы и картинки, а libxlsxwriter
умеет только писать. OpenXLSX сам построен на pugixml и miniz. Здесь эти библиотеки используются напрямую: [pugixml](https://pugixml.org/) для XML
и [miniz](https://github.com/richgel999/miniz) для zip и deflate. Это даёт полный контроль над
многопоточностью и над тем, какие части книги меняются.

## Тесты

GoogleTest, 65 тестов:

- цвета, критерий красного, tint, палитры;
- разбор стилей и темы;
- сдвиг формул;
- обработка листа (включая общие формулы и префиксы пространств имён);
- zip, включая параллельное чтение и склейку кусков deflate;
- пул потоков;
- командная строка;
- сквозные тесты на настоящих `.xlsx`, включая большой случайный лист, результат которого
  сравнивается при разном числе потоков.

Дополнительно проверено:

- ThreadSanitizer не находит гонок;
- результаты открываются без ошибок в openpyxl и LibreOffice;
- Windows-сборка под wine даёт побайтно тот же файл, что и Linux-сборка.

```sh
ctest --test-dir build -j4
```

## Производительность

Тестовая книга: 4 листа по 250 000 строк × 8 столбцов. В архиве 45 МБ, в распакованном виде
317 МБ XML. Около 3% строк содержат красную ячейку. Машина с 4 ядрами, Linux, сборка Release,
команда `--all-sheets -r 2`:

| Потоки | Разбор XML | Поиск | Очистка и сериализация | Сжатие и запись | Всего |
|---|---|---|---|---|---|
| `-j 1` | 7.2 с | 1.2 с | 6.5 с | 24.4 с | 39.7 с |
| `-j 2` | 4.7 с | 0.6 с | 1.6 с | 13.2 с | 21.0 с |
| `-j 4` | 3.3 с | 0.6 с | 1.5 с | 11.4 с | 18.3 с |
| `-j 4 --compression-level 1` | 4.6 с | 0.8 с | 2.0 с | 4.3 с | 12.2 с |

Больше всего времени уходит на сжатие XML обратно в архив. Если размер файла не критичен,
заметно помогает `--compression-level 1`: файл получился на 16% больше (52 МБ вместо 44 МБ).

## Ограничения

- Поддерживается только формат `.xlsx` (Office Open XML). Старый `.xls` и двоичный `.xlsb` не поддерживаются.
- Учитывается только собственный стиль ячейки. Не учитываются:
  - цвет из условного форматирования;
  - стили, заданные целой строке или столбцу для ячеек, которых нет в файле.
- Строки очищаются, но не удаляются: строки ниже не сдвигаются, ссылки на очищенные ячейки
  в формулах других ячеек остаются.
